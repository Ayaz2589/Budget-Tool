## Implementation Details

### Change 1: DsActionBar — Add `mobileOnly` prop

**File**: `src/components/ds/DsActionBar.tsx`

- Add optional `mobileOnly?: boolean` prop (default: `true`) for backward compatibility
- When `mobileOnly` is `false`:
  - Remove `md:hidden` from outer container
  - Add responsive bottom positioning: keep `bottom-[calc(env(safe-area-inset-bottom)+84px)]` for mobile, add `md:bottom-4` for desktop (no bottom nav on desktop)
- When `mobileOnly` is `true` (default): behavior unchanged

### Change 2: Dashboard — Replace header buttons with floating action bar

**File**: `src/pages/dashboard/Dashboard.tsx`

- Remove the `!isMobile` conditional wrapper around DsActionBar (currently only renders on mobile)
- Pass `mobileOnly={false}` to DsActionBar so it renders on desktop too
- Remove Add Expense, Add Income, and Settings buttons from DsSectionHeader `actions` prop
- Keep a single icon-only "Manage Widgets" button (Grid2X2 icon) in the header `actions`
- Remove "Reset Layout" button from header (moved to widget catalog)

### Change 3: DsWidgetCatalog — Add Reset Layout footer

**File**: `src/components/ds/DsWidgetCatalog.tsx`

- Add `onReset?: () => void` optional prop
- When provided, render a "Reset Layout" button in the SheetFooter
- The confirmation dialog stays in Dashboard.tsx — the catalog just triggers the callback
- Actually, simpler: Add `onResetRequest` callback that opens the existing AlertDialog in Dashboard

### Change 4: Remove isMobile guard for DsActionBar

**File**: `src/pages/dashboard/Dashboard.tsx`

- Remove the `{isMobile ? <DsActionBar>...</DsActionBar> : null}` conditional
- Render `<DsActionBar mobileOnly={false}>` unconditionally with the 3 buttons
- The DsActionBar component handles responsive positioning internally
