# Implementation Plan: Migrate Google Sync to genjutsu-db

**Branch**: `020-sync-genjutsu-db` | **Date**: 2026-02-22 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/020-sync-genjutsu-db/spec.md`

## Summary

Replace the 12-file hand-rolled Google Sheets HTTP layer (`src/lib/sheets/`) with typed genjutsu-db model definitions and client operations. The genjutsu-db library provides `defineModel()` for schema definition, `createClient()` for typed repositories, and `batchSync()` for atomic multi-sheet writes — directly replacing the custom transport, per-domain CRUD modules, and batch sync orchestration. SyncContext/SheetSetupContext orchestration (auto-sync, rate limiting, change detection) remain unchanged — only the underlying I/O calls swap.

## Migration Strategy

### Phase approach (incremental, per Constitution Principle VI):

1. **Add genjutsu-db dependency** — `bun add genjutsu-db`
2. **Define models** — Create `models.ts` with all 7 domain schemas matching existing column layouts exactly
3. **Create client factory** — `client.ts` with token provider pattern wrapping existing OAuth flow
4. **Migrate push (syncToSheets)** — Replace `syncAllSheetsBatch()` with `db.batchSync()` in SyncContext
5. **Migrate pull (pullFromSheet)** — Replace per-domain `readXxxFromSheet()` with `db.repo("x").readAll()`
6. **Migrate sheet setup** — Replace `ensureSheetsExist()` with `db.ensureSchema()`, formatting with `db.applyFormatting()`
7. **Delete old modules** — Remove the 7+ files that are fully replaced
8. **Verify** — All tests pass, build succeeds, sync works end-to-end

### Special cases:

- **Data blob (Data!A1)**: Raw cell read/write via genjutsu-db transport utilities or kept as direct API call. Not a model.
- **Totals sheet**: Dynamic columns based on owner count. Keep existing `buildTotalsValues()` but write via genjutsu-db's raw `updateSheet()` or batch payload.
- **Legacy expense rows**: Preserve `hasIdColumn()` detection in the Expense model's `parseRow` override using genjutsu-db's raw `SheetSchema` pattern.
- **Utility re-exports**: `generateId`, `parseAmount`, `normalizeDate`, `extractSpreadsheetId`, `hasIdColumn`, `findMissingHeaders` — all re-exported from genjutsu-db. Update import sites.
