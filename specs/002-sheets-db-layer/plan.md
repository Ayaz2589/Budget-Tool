# Implementation Plan: Google Sheets Database Layer

**Branch**: `002-sheets-db-layer` | **Date**: 2026-02-18 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/002-sheets-db-layer/spec.md`

## Summary

Refactor the existing 12-module Google Sheets sync system (`src/lib/sheets/`) into a self-contained database-style data layer (`src/lib/sheets-db/`) with a client factory pattern, typed error handling, input validation, output normalization, and zero external imports. The module will be extractable as a standalone library. All existing sync functionality is preserved — zero user-facing behavior changes.

## Technical Context

**Language/Version**: TypeScript 5.x (strict mode)
**Primary Dependencies**: None (pure `fetch`-based, no external libraries)
**Storage**: Google Sheets v4 REST API (client-side, no backend)
**Testing**: Bun test runner + happy-dom
**Target Platform**: Browser (React 19 SPA, Vite 7)
**Project Type**: Web application (single frontend, no backend)
**Performance Goals**: No regression from current sync performance
**Constraints**: Zero external imports from host app, incremental migration, all 11 financial guard tests must pass throughout
**Scale/Scope**: 12 existing modules to refactor, ~1,600 lines of sheets code, 4 consumer files to update

## Complexity Tracking

> **Filled because Constitution Check Principle VII requires justification.**

| Violation | Why Needed | Simpler Alternative Rejected Because |
| --------- | ---------- | ------------------------------------ |
| Client factory pattern (`createSheetsClient`) | Eliminates repeated `(token, spreadsheetId)` params across 20+ function calls. Required for library extraction (FR-008). | Passing token/id to every call: error-prone, leaks connection management to consumers, prevents extraction. |
| Repository objects per entity | Groups related operations (read/write/append) under named namespaces. Required for clean public API (FR-007). | Flat function exports (current approach): requires importing 15+ named functions, no discoverability, no IDE autocomplete grouping. |
| Typed error discriminated union | Enables callers to handle auth vs rate-limit vs validation errors differently (FR-010). | String error messages: forces regex matching, no type safety, callers can't reliably branch on error type. |
| Internal type definitions | Required for zero-coupling boundary (FR-008) and library extractability (User Story 4). | Importing from `@/types/core`: creates hard dependency on host app, prevents library extraction. |
